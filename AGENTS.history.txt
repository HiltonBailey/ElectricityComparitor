- **Data logger gap detection and filling** — calculate_costs preprocesses all CSV rows into `allRows` array, detecting gaps >6min between consecutive timestamps. Missing 5-min slots are filled with evenly-distributed kWh from the accumulated gap energy, assigned correct TOU period per slot, with synthetic rows flagged (`_syn: true`). All three processing loops (PEA, dailyData, csvByDate) iterate `allRows`. AEMO price from `sensor.aemo_nemweb_nsw1_realtime_price` history (pre-fetched hourly via `inject_aemo_history` sub-flow) used for synthetic rows, falling back to interpolation. Corrected CSV rows written back to `/share/file_notifications/5minelec.csv` via `write_fixed_csv` file node (output 2). HA persistent notification sent for each new gap. Deduped via `lastGapAlert`.
- **CSV write-back fix for data logger gaps** — gap-filling write-back was using `ga.kwh` (total gap energy) for cumOff interpolation and leaving cumSh/cumPk static (no interpolation). Fixed by storing per-period gaps (`gapOff`, `gapSh`, `gapPk`) in `gapAlerts` and using them in the `csvLines` write-back to correctly interpolate each period's cumulative values. Without this fix, corrected CSV rows had nonsensical cum values (total gap assigned to cumOff alone, cumSh/cumPk flat).
- **CSV file never updated** — `fixMsg` set `filename` to the backup path (`5minelec.csv.backup.TIMESTAMP`), overriding `write_fixed_csv`'s configured path. Both `write_csv_backup` and `write_fixed_csv` wrote to the backup file; the real CSV was never modified. Split to 4 outputs: output 2 → backup (with `filename`), output 3 → `write_fixed_csv` (no `filename`, uses its config path `/share/file_notifications/5minelec.csv`).
- **Plateau HA notification** — added `plateauAlertMsg` sent via output 1 (`ha_rest_api_notify`) with dedup via `lastPlateauAlert` flow var and notification_id `energy_plateau_alert`. Previously the plateau write-back path sent `gapAlertMsg` (which was `null` when only plateaus existed).
- **Two-pass data correction** — plateau preprocessing handles SENSOR PLATEAUS (stale cum values in consecutive CSV rows, e.g., logger stuck from 00:05–11:25 on June 29, 0kWh gap); gap-filling loop in allRows handles DATA LOGGER GAPS (missing CSV rows, e.g., HA automation down 12:30–13:59 with 13.388kWh catch-up at 14:04:59 — 19 synthetic rows interpolated, spike eliminated)
- **June 29 data-logger-gap debugging resolved** — "afternoon plateau" was actually a CSV gap (rows 12:30–13:59 absent from file), correctly handled by allRows gap-filling; 5-min detail now shows 0 intervals >1kWh for that day
- **`\n` JSON escaping corruption fixed** — `detect_gaps_for_ha` and `process_ha_and_fill` had `split('\n')` and `join('\n')` inside function code. The `\n` inside single-quoted JS string literals was interpreted by JSON as a literal newline character, producing `split('" + chr(10) + "')` at runtime — a JS SyntaxError ("Invalid or unexpected token"). Root cause: an earlier `POST /flows` deploy round-tripped the code through `json.loads` → `json.dumps`, which re-encoded `\n` as actual newlines. Fixed by replacing with `String.fromCharCode(10)` pattern. File-in nodes also changed from `encoding=none` (Buffer) to `encoding=utf8` (string). Rule: always use `String.fromCharCode(10)` for newline literals in function node code.
- **Cross-day gap overlap bug fixed** — The data logger catch-up fix (jumpKwh > 10 && gapMin2 <= 6) created 25 synthetic rows spanning 00:00-02:00 on the new day, but actual CSV rows at the same timeKeys (00:05-02:00) were still pushed to allRows. In the csvByDate loop, actual rows overwrote synthetic entries at the same timeKey, causing 24/25 of the distributed jump deltas to be lost. The 5-min detail total was undercounted by ~24/25 × jumpOff (0.832 kWh for this case). Fixed by tracking `lastSyntheticMins` after the cross-day catch-up and skipping actual rows whose time falls within the synthetic range. Also cleaned up all active `node.warn()` calls in function nodes.
- **NR v5 `require('http')` crash fixed (v2.16)** — `build_sensor_messages` used `require('http')` to make direct HTTP POST/DELETE calls to HA, which throws `ReferenceError: require is not defined` in Node-RED v5 function nodes. This crashed BSM on line 1, so NO individual retailer sensors, cheapest, or savings sensors were ever updated. Fixed by rewriting BSM to use `node.send()` with proper msg objects (`msg.url` + `msg.payload`) routed to HTTP request nodes configured with `{{{url}}}` mustache templates and node-level auth headers. Also removed redundant `msg.headers` from build_daily_summary, build_daily_detail, build_five_min_detail, build_monthly_summary, and build_seasonal_report (auth already configured on HTTP request nodes). Removed `CALC_COSTS ENTRY` debug warn from calculate_costs.
- **HA history-based gap filling** — new flow path: `detect_gaps_for_ha → prepare_ha_queries → httpRequest×4 (offpeak/shoulder/peak/export) → process_ha_and_fill → calculate_costs`. Queries HA sensor history at hour boundaries within gaps, uses real cumulative values as anchor points for piecewise linear interpolation instead of blind linear averaging. Falls back to linear interpolation when HA data unavailable. Deploys as v2.11.


### Fixed
- **Inline `//` comments eating all code after them** — entire generated JS was on one line (no newlines), so `// params not needed` commented out the `for` loop, and `// Standard form POST` commented out `});})();function revertConfig()` incl. all closing braces. Changed to `/* */` block comments. Added favicon `<link>` and `</body></html>` closing tags to fix browser JS errors.
- **File-in node Buffer rejected by fallback_config_1** — `read_retailer_config_1` with `encoding: none` returns a Node.js Buffer, but `fallback_config_1`'s `typeof msg.payload !== 'string'` check silently discarded it → `store_config` never called → `flow.get('retailers')` always undefined → every 5-min cycle crashed on `flowPower.fixed_export`. Added Buffer→string conversion at start of `fallback_config_1`.
- **Config editor GET timeout** — root cause was `\n` escape sequences in JavaScript string literals getting double-escaped by Python json.dump when rewriting the flow JSON; replaced all `'\n'` with `String.fromCharCode(10)` (aliased as `NL`) to avoid JSON encoding issues; function code now stored in `config_func_code.js` and embedded via Python file read + json.dump
- **Config editor URL changed** — GET handler moved to `/api/retailer-editor` to avoid Node-RED routing corruption at the old `/api/retailer-config` URL (which persisted across deploys); POST handler moved to `/api/retailer-config/save`; editor accessible at `http://192.168.50.100:1880/endpoint/api/retailer-editor`
- **Config editor save not persisting** — `write_retailer_config_1` file node had 2 outputs configured (`wires: [[http_response], [store_config]]`) but standard Node-RED `file` node has only 1 working output; `store_config` on output 2 never received the message, so `flow.set('retailers', ...)` was never called after save; fixed by wiring both `http_config_post_response_1` and `store_config` to output 0
- **Template node overwriting file config every 5 min** — `retailer_config_template` was wired directly to `store_config` (bypassing `fallback_config_1`) and triggered by the 5-min inject, overwriting file values with defaults before the file-in node could read the actual CSV; fixed by removing template from inject wires and adding a one-shot startup inject
- **Template/file race condition** — both template and file-in competed to set `flow.get('retailers')` every cycle; fixed by routing both through `fallback_config_1` which tracks a `_fromFile` flag — template data is only passed on first boot when no retailers exist yet
- **Revert button broken** — `localStorage.removeItem("retailerConfigBackup")` ran on every successful save, deleting the revert point; fixed by saving backup on first page load (IIFE) and only deleting on successful revert; the save handler no longer touches the backup at all
